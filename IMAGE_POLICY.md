# Top King — правила работы с игровыми изображениями

## Главный принцип
На сайте нельзя использовать выдуманные, сгенерированные, стоковые или случайно найденные изображения вместо оригинальных изображений Hamster King.

## Источники по приоритету
1. `assets/` — уже одобренная библиотека изображений сайта.
2. Изображение, которое пользователь прислал в чат и явно одобрил для сайта.
3. Канонический HAR-каталог Hamster King (`game-assets/catalog.js`).
4. Публичный официальный источник Hamster King — только как кандидат на согласование.

## Что запрещено
- Генерировать картинку для замены игрового изображения.
- Использовать стоковые иллюстрации или изображения из сторонних игр.
- Подставлять первое похожее изображение из поиска.
- Подменять неизвестную картинку эмодзи/иконкой без явной просьбы.
- Удалять существующий эмодзи, guide-emoji или игровой маркер только потому, что точная замена пока не найдена.
- Добавлять новую внешнюю картинку на сайт без подтверждения пользователя.

## Сохранение исходной семантики
Существующий эмодзи или `guide-emoji` считается маркером конкретного игрового объекта. При обновлении дизайна нужно сохранять его позицию и смысл.

Если точное соответствие оригинальному игровому ассету подтверждено — заменить маркер на этот ассет в том же месте.

Если точное соответствие не подтверждено — исходный маркер оставить без изменений.

## Режим кандидата
Если нужного изображения нет среди уже подтверждённых ассетов или соответствие неоднозначно, показать пользователю **ровно три наиболее вероятных варианта**:

1. **Вариант 1** — [ассет / игровой путь / почему подходит]
2. **Вариант 2** — [ассет / игровой путь / почему подходит]
3. **Вариант 3** — [ассет / игровой путь / почему подходит]
4. **Свой вариант** — пользователь сам показывает нужное изображение.

До выбора пользователя спорный элемент на сайте не заменять и не удалять.

Для каждого кандидата по возможности показывать превью, игровой путь и место сайта, куда он предлагается.

## После подтверждения
После подтверждения:
1. Сохранить изображение в подходящую папку `assets/...`, если это возможно.
2. Добавить запись в `assets/image-manifest.json`.
3. Использовать утверждённый путь на сайте.
4. Повторно не спрашивать подтверждение для той же записи, пока пользователь не попросит заменить изображение.

## Поведение при неопределённости
Не угадывать и не принимать решение за пользователя. Если остаётся сомнение хотя бы между несколькими игровыми ассетами — применить схему **3 варианта + 4-й «свой вариант»**.

## Правило для будущих правок сайта
При любой задаче, где появляется или заменяется иллюстрация:
1. Проверить `assets/image-manifest.json`.
2. Проверить исходный маркер/эмодзи и его смысл.
3. Проверить HAR-каталог.
4. Однозначное совпадение — заменить.
5. Неоднозначное совпадение — ничего не менять и вынести 3 варианта на выбор пользователя.
